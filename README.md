# Multi Clone App — Step 5: Installed App Discovery

This milestone connects the UI to Android's list of launchable installed apps.

## What works in this step
- The Add App page reads launchable app names/package IDs from Android.
- The user can create app-entry records in My Clones.
- Open Clone launches the original installed app from the selected entry.

## Important limitation
This is **not real app cloning**. Entries currently share the original package and do not have separate app storage, login sessions, or independent app processes. True cloning needs an Android virtualization/container implementation and app compatibility testing; a WebView bridge alone cannot provide that.

## Build notes
- Package: `com.multiclone.app`
- Min SDK 23, target SDK 35, compile SDK 36.
- Android package visibility is used to query launchable apps. `QUERY_ALL_PACKAGES` is subject to Google Play policy review and must be justified if publishing.
- This project still needs a Gradle Wrapper (`gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`, `gradle-wrapper.properties`) if your GitHub Actions workflow expects it. Use the wrapper files generated by Android Studio for the same Gradle version.

## Test
1. Replace your current project files with this project, or copy the modified files into your existing project.
2. Build and install the APK.
3. Open Add App and check whether installed launchable apps appear.
4. Add one app entry, open its details, then tap Open Clone. The original app should open; the UI clearly notes that isolated cloning is not implemented yet.

Do not describe this milestone as a working multi-cloner until a separate app-container/virtualization engine is implemented and tested.
